# Этап 1 — Ядро

Дата: 27.08.2026.

## Что собрано

| Слой | Модуль | Что делает |
|---|---|---|
| Ingest | `application.py`, `ingest.py` | secret_token, дедуп в Redis, bounded queue, быстрый 200 OK |
| Hard filter | `hard_filter.py` | боты, 777000, исходящие владельца, не-приватные чаты, контент без текста |
| Gate | `gate.py` | is_active, kill switch, исключения, quiet-окна с переходом через полночь, один ответ на окно |
| Классификатор | `classifier.py`, `llm.py` | один вызов Claude со схемой JSON, таймаут 8 с, словарный fallback, порог уверенности |
| Задержка | `delayed.py`, `workers.py` | 60–240 с в Redis sorted set, доставка отдельным воркером |
| Отправка | `sender.py` | `BUSINESS_CHAT_INACTIVE` без ретраев, `FLOOD_WAIT` + 5 с, `BUSINESS_CONNECTION_INVALID` → алерт, прочее — 3 попытки |
| Dry run | `pipeline.py`, `notifications.py` | превью владельцу с кнопками, вердикт в `shadow_feedback` |
| Утренний список | `morning.py` | 08:00 в таймзоне владельца, доставка один раз |
| Хранилище | `storage.py`, `models.py`, `migrations/` | всё привязано к `connection_id`, тел сообщений нет |

Порядок пайплайна: hard filter → gate → классификация → **claim окна** →
отложенная задача → проверка «владелец ответил сам» → отправка или превью →
лог → money-флаг.

## Отклонения от `tech-stack.md`

1. **Окно занимается при постановке задачи, а не при отправке.** Иначе пять
   сообщений с интервалом в минуту проходят gate до первой отправки и дают пять
   ответов вместо одного (FR-7). Отменённый claim стоит одного пропущенного
   автоответа — это дешевле дубля.
2. **Превью не цитирует сообщение контакта.** Решение ждёт задержку в Redis, а
   тела сообщений не хранятся нигде (NFR-2), поэтому макет §6.6 с цитатой
   нереализуем без нарушения требования. Владелец видит время, контакт,
   категорию и текст будущего ответа.
3. **Money-флаг ставится и в dry-run.** Утренний список уходит только владельцу,
   а неделя наблюдения должна прогонять тот же путь, что и боевой режим.
4. **Список `action` расширен**: `skipped_inactive`, `skipped_kill_switch`,
   `skipped_unsupported_content` — FR-13 требует лог всех решений.
5. **Добавлена колонка `connections.owner_chat_id`** — превью и утренний список
   уходят в личку владельца, её идентификатор даёт `BusinessConnection`.
6. **PoC-эхо и `POC_ECHO_ENABLED` удалены.** Их роль страховки взял `dry_run`,
   включённый по умолчанию для нового подключения. `ALLOWED_CHAT_IDS` остался
   необязательным ограничением на время отладки.

## Проверено на живом аккаунте 27–28.08.2026

- Превью в dry-run: владельцу приходит карточка с кнопками, контакту не уходит
  ничего. Задержка отработала 129 с из диапазона 60–240.
- Вердикт по кнопке записан в `shadow_feedback` — после того как webhook был
  подписан на `callback_query`.
- Пять сообщений подряд дали одну карточку и четыре
  `skipped_window_limit`.
- Ручной ответ владельца отменил отложенный ответ с
  `skipped_owner_replied`.
- Временное исключение дало `skipped_excluded` без постановки задачи в Redis.
- Денежное сообщение классифицировано как `money` с шаблоном
  `money_priority`; утренний список доставлен один раз, повторный tick не дал
  дубля.
- Отложенная задача пережила рестарт только `app` и доставила ровно одну
  карточку; Redis и Postgres при этом не перезапускались.
- Миграции прогнаны против Postgres в обе стороны: base → head → base → head.
