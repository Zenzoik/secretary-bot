# Этап 0 — PoC Telegram Business

Дата проверки документации: 27.08.2026.

## Что уже подтверждено документацией

- Bot API присылает `business_connection`, `business_message`,
  `edited_business_message` и `deleted_business_messages`.
- `sendMessage` принимает `business_connection_id`.
- Для ответа необходимо право `can_reply`; оно действует в приватных чатах с
  входящим сообщением за последние 24 часа.
- Официальная документация Telegram указывает, что подключённые business-боты
  доступны также пользователям без Premium. Практический тест ниже всё равно
  обязателен, поскольку это блокирующий вопрос Этапа 0.

Источники:

## Структура `BusinessConnection.rights`

Все поля опциональны и имеют значение `true`, когда право выдано:

| Поле | Назначение |
|---|---|
| `can_reply` | Отправка и редактирование сообщений в доступном 24-часовом окне |
| `can_read_messages` | Отметка входящих сообщений прочитанными |
| `can_delete_sent_messages` | Удаление сообщений, отправленных ботом |
| `can_delete_all_messages` | Удаление любых личных сообщений в управляемых чатах |
| `can_edit_name` | Изменение имени business-аккаунта |
| `can_edit_bio` | Изменение bio |
| `can_edit_profile_photo` | Изменение фотографии профиля |
| `can_edit_username` | Изменение username |
| `can_change_gift_settings` | Изменение настроек приватности подарков |
| `can_view_gifts_and_stars` | Просмотр подарков и баланса Stars |
| `can_convert_gifts_to_stars` | Конвертация обычных подарков в Stars |
| `can_transfer_and_upgrade_gifts` | Передача и улучшение подарков |
| `can_transfer_stars` | Передача Stars и операции улучшения/передачи подарков |
| `can_manage_stories` | Публикация, изменение и удаление историй |

PoC требует `can_reply` для ответа и `can_read_messages` для явной отметки
входящего прочитанным после успешного ответа. При получении
`business_connection` фактический объект `rights` целиком попадает в
структурированную строку лога. Токен и тела сообщений не логируются.

Фактическое подключение 27.08.2026 выдало права `can_reply`,
`can_read_messages`, `can_delete_sent_messages` и `can_delete_all_messages`.
Права удаления PoC не использует. После корректировки настроек Chat Automation
Telegram прислал состояние с `can_reply=true`, затем владелец осознанно добавил
`can_read_messages=true`, чтобы ответ бота не оставлял входящее непрочитанным.

## Ручной сценарий

1. Создать отдельного тестового бота в `@BotFather` и включить Business Mode.
2. Заполнить `.env`; оставить `POC_ECHO_ENABLED=false`.
3. Запустить приложение и предоставить ему публичный HTTPS URL.
4. Выполнить `uv run secretary-set-webhook`.
5. Подключить бота к тестовому аккаунту с правами ответа и отметки прочитанным.
6. Убедиться, что в логе есть событие `business_connection` с `is_enabled=true`
   и `rights.can_reply=true`.
7. Ограничить область тестовым контактом, включить `POC_ECHO_ENABLED=true` и
   перезапустить приложение.
8. Написать тестовому аккаунту с тестового контакта. Проверить, что тот же текст
   пришёл контакту от имени владельца.
9. Ответить контакту вручную от владельца. Проверить, появляется ли этот исходящий
   текст как `business_message`; сам текст не должен оказаться в логах.
10. Проверить аккаунт владельца без Premium тем же подключением.
11. После теста вернуть `POC_ECHO_ENABLED=false`.
12. Для проверки истёкшего окна использовать отдельный чат без входящих более
    24 часов и зафиксировать точный ответ Telegram. PoC намеренно не предоставляет
    произвольную команду отправки, чтобы исключить случайные сообщения контактам.
