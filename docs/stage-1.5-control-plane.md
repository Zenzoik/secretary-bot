# Этап 1.5 — Control plane

Дата проверки: 28.08.2026.

## Что реализовано

- `/status` показывает состояние, dry-run/live, временную паузу и таймзону.
- `/off` включает сохраняемый kill switch; `/on` выключает его и снимает mute.
- `/mute N` сохраняет дедлайн на N часов. Gate сравнивает его с текущим
  временем, поэтому работа возобновляется сама и не зависит от таймера процесса.
- `/today` агрегирует решения за локальные сутки владельца без тел сообщений.
- `/live` создаёт отдельное подтверждение на пять минут. Команда сама не меняет
  `dry_run`; подтверждение потребляется атомарно, отмена, истечение срока и
  `/off` его аннулируют.
- `/start bizChat<user_chat_id>` открывает карточку контакта из кнопки
  Telegram Manage Bot.
- Карточка умеет исключить контакт навсегда, до локальной полуночи или назначить
  ему принудительный обычный/денежный шаблон.

Обычные команды и все callbacks принимаются только от сохранённого владельца.
Тела входящих сообщений control plane не хранит.

## Живая проверка

| Сценарий | Результат |
|---|---|
| `/status` | Ответ совпал с БД: включён, dry-run, без паузы, `Europe/Kyiv` |
| `/off` → `/status` | Kill switch сохранился и сразу отразился в статусе |
| `/on` → `/status` | Kill switch и временная пауза сняты, dry-run сохранён |
| `/mute 3` → `/status` | Дедлайн записан на три часа вперёд и показан по Киеву |
| `/today` | Все агрегаты дословно совпали с PostgreSQL |
| `/live` без подтверждения | Остался dry-run; создан только запрос на пять минут |
| Отмена `/live` | Запрос удалён, dry-run сохранён |
| Manage Bot | Из реального тестового чата открылась карточка этого контакта с корректной статистикой |
| Не трогать сегодня | Создано активное исключение до ближайшей полуночи Киева |
| Исключить навсегда | Следующее сообщение получило `skipped_excluded`, Redis остался пуст |
| Свой шаблон | Обычное сообщение сохранило `general`, но получило `money_priority` и соответствующий текст |

После проверки временные исключения, персональный override и quiet-window claim
тестового контакта удалены. Соединение оставлено в состоянии `dry_run`,
`kill_switch=false`, без mute и незавершённого live-подтверждения.

## Что проверено автоматически

- уже поставленная задача блокируется `/off` и активным mute;
- mute перестаёт блокировать точно на границе дедлайна;
- неизвестный пользователь не может выполнять команды и callbacks;
- просроченное, отменённое и аннулированное через `/off` подтверждение не
  включает live;
- персональный `force_template` меняет шаблон задачи, не меняя её категорию.
