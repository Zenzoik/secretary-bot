# Этап 1.7 — личность, доставка и украинский UI

Дата закрытия: 30.08.2026.

## Что реализовано

- В `connections` добавлены `sender_identity`, границы задержки владельца,
  границы задержки бота и `mark_read`. Миграции: `20260830_0009` и
  `20260830_0010`.
- `bot` — значение по умолчанию. Ответ отправляется через Telegram Business от
  подключённого аккаунта. Telegram показывает нативную метку подключённого бота
  внизу сообщения; дополнительная подпись в тело не добавляется. Ограничение
  платформы и живой тест зафиксированы в `tech-stack.md`.
- `owner` сохраняет прежний путь отправки без подписи. Случайная задержка берётся
  из полей подключения; значения по умолчанию — 10–60 секунд.
- Для `bot` используется случайная настраиваемая задержка, по умолчанию 5–60 секунд.
- Личность копируется в `ReplyTask`, поэтому изменение настройки не меняет уже
  поставленную в Redis задачу.
- `mark_read=false` по умолчанию. `readBusinessMessage` вызывается только после
  успешной отправки, при включённой настройке и наличии `can_read_messages`.
- Отключение Business Connection или отзыв `can_reply` включает kill switch,
  деактивирует подключение, очищает его очередь и уведомляет владельца.
- Отзыв `can_read_messages` не блокирует получение и ответы; отключается только
  отметка прочитанным.
- Временная ошибка доставки возвращает задачу в Redis: до трёх попыток с интервалом
  5 секунд. При остановке worker возвращает весь уже захваченный пакет задач.
- Весь видимый интерфейс переведён на украинский и собран в `texts.py`.
  Классификатор остаётся многоязычным намеренно.

```bash

  --cov-report=term-missing tests/test_gate.py

```

Результат на момент закрытия: 211 тестов прошли, `gate.py` — 100% statement и
branch coverage, SQL всех миграций до `20260830_0010` генерируется без ошибок.

Архитектурный тест `tests/test_texts.py` не допускает пользовательскую кириллицу
в `control.py`, `notifications.py`, `morning.py`, `pipeline.py`, `runtime.py` и
`templates.py`: тексты должны находиться в едином каталоге `texts.py`.

## Живая проверка после развёртывания

Проводится только с выбранным тестовым контактом и в `dry-run`, пока отдельно не
подтверждён live:

1. Открыть панель бота и убедиться, что клавиатура и ответы украинские.
2. Отправить сообщение от тестового контакта в нерабочее окно.
3. Через случайные 5–60 секунд проверить превью: в теле находится только текст
   шаблона, без подписи секретаря; контакт ничего не получил.
4. Убедиться, что сообщение контакта осталось непрочитанным при `mark_read=false`.
5. Для проверки `owner` временно выставить `sender_identity=owner` и одинаковые
   границы задержки, например 10/10; новое превью должно появиться через 10 секунд.
6. Вернуть `sender_identity=bot`. Уже поставленная до переключения задача должна
   сохранить режим `owner`.
7. Включить `mark_read=true` только для теста, отправить сообщение и после успешной
   отправки проверить две галочки. Следующее сообщение того же контакта должно
   снова попасть в webhook. После теста вернуть `mark_read=false`.
8. Отозвать только `can_read_messages`: ответы продолжаются, чтение — нет, владельцу
   приходит предупреждение.
9. Отозвать `can_reply` либо отключить Business Connection: очередь подключения
   очищается, kill switch включается, владельцу приходит аварийное уведомление.
