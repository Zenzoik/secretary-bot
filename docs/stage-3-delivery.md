# Этап 3 — Mini App и веб-настройки

Дата реализации: 01.09.2026

## Результат

Один адаптивный интерфейс обслуживает два способа входа:

- Telegram Mini App — подписанный `initData` передаётся в заголовке API;
- обычный браузер — одноразовая ссылка обменивается на `Secure`, `HttpOnly`,
  `SameSite=Lax` cookie. Ссылка действует 15 минут и используется один раз,
  browser-сессия — 30 дней или до явного выхода.

В постоянной клавиатуре бота остались только четыре быстрых действия:
`📊 Статус`, `🗓 Сьогодні`, питание и `⏸ Пауза`. Системная кнопка меню
`Налаштування` регистрируется после `/start` и открывает Mini App.

## Экраны

### Огляд

- отправка с подписью секретаря или без неё от владельца;
- минимальная и максимальная задержка;
- отдельная минимальная задержка режима секретаря;
- отметка входящего сообщения прочитанным после успешной отправки;
- состояние live/dry-run и выданных Telegram Business прав.

### Розклад

- timezone из IANA;
- до восьми временных окон;
- набор дней, начало, конец и активность окна;
- переход через полночь поддерживается.

После сохранения pipeline загружает новые значения из PostgreSQL для следующего
сообщения. Перезапуск контейнера не требуется.

### Контакти

Список строится из контактов, от которых уже были входящие сообщения. Доступны:

- поиск по имени или Telegram ID;
- отсутствие исключения, исключение навсегда или до даты;
- до восьми персональных временных окон.

Если у контакта есть персональные окна, они заменяют общий график. Пустой список
возвращает контакт к общему графику. Данные другого владельца API не возвращает.

### Шаблони

Редактируются активные шаблоны `off_hours_default` и `money_priority`. Пустой
текст не принимается, длина ограничена 1000 символами.

### Класифікація

Для действующих направлений `general` и `money` редактируются название,
описание, ключевые слова и активность `money`; `general` остаётся обязательным
fallback. Также сохраняются системный prompt, модель и минимальная уверенность.

Архитектура таблицы направлений подготовлена к расширению, но добавление новых
кодов до пяти требует отдельного изменения ядра классификатора и ограничения
`message_log.category` по FR-18. На Этапе 3 без AI произвольные новые коды не
создаются, чтобы UI не обещал поведение, которого ещё нет в pipeline.

### Самарі

Сохраняются локальное время и числовой ID Telegram-канала. Генерация и отправка
суточного саммари относятся к Этапу 4 и пока не запускаются.

### Журнал

Показывает только технические решения за последние 30 дней. Есть фильтры по
Telegram ID контакта и действию. Тела входящих сообщений в ответ API не входят.

## REST API

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/bootstrap` | Состояние подключения и все настройки для первого рендера |
| `PUT /api/v1/delivery` | Отправитель, задержка, отметка прочитанным |
| `PUT /api/v1/schedule` | Timezone и общий график |
| `GET /api/v1/contacts` | Контакты текущего владельца и поиск |
| `PUT /api/v1/contacts/{id}` | Исключение и персональные окна |
| `PUT /api/v1/templates` | Шаблоны ответа |
| `PUT /api/v1/classifier` | Направления, prompt, модель и порог |
| `PUT /api/v1/summary` | Время и канал будущего саммари |
| `GET /api/v1/logs` | 30-дневный журнал с фильтрами |
| `POST /api/v1/auth/browser-link` | Одноразовая ссылка для браузера |
| `POST /api/v1/auth/logout` | Отзыв текущей browser-сессии |

Во всех endpoints сначала проверяются подпись Telegram или browser-cookie,
активный доступ пользователя, завершённый onboarding и принадлежность Business
Connection этому владельцу.

## Живой чек-лист владельца

Перед тестом оставить в Telegram Chat Automation только тестовый контакт.

1. В диалоге с ботом отправить `/start`. Проверить четыре кнопки постоянной
   клавиатуры и системную кнопку **Налаштування**.
2. Открыть **Налаштування**. Должен появиться экран `Огляд` без запроса логина.
3. Открыть по очереди все семь разделов. На узком экране навигация должна
   оставаться доступной, формы не должны выходить за ширину.
4. В `Розклад` добавить отдельное тестовое окно, включающее ближайшие минуты,
   сохранить и получить зелёное подтверждение. Контейнер не перезапускать.
5. С тестового контакта отправить сообщение. Оно должно обработаться уже по
   новому окну. После проверки вернуть исходный график и сохранить.
6. В `Шаблони` временно добавить маркер `ТЕСТ-3` в обычный ответ, сохранить и
   отправить новое сообщение в следующем допустимом окне. Проверить маркер,
   затем вернуть исходный текст.
7. В `Контакти` выбрать тестовый контакт, включить исключение навсегда и
   сохранить. Новое сообщение не должно создавать ответ. Затем выбрать
   `Немає`, добавить персональное окно, сохранить и проверить обработку.
8. В `Огляд` переключить личность и безопасные границы задержки, сохранить,
   обновить страницу и убедиться, что значения сохранились. После теста вернуть
   нужный режим.
9. В `Журнал` отфильтровать тестовый Telegram ID и по очереди действия
   `replied`/`skipped_excluded`. Записи старше 30 дней показываться не должны.
10. Нажать **Відкрити у браузері**, открыть скопированную ссылку и проверить те
    же семь экранов. Повторное открытие той же ссылки должно быть отклонено.
11. В браузере нажать **Вийти** и убедиться, что настройки больше не видны.

Этап можно закрыть окончательно после прохождения пунктов 1–11 владельцем.
